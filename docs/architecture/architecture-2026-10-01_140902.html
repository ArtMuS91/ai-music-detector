AI Music Detector — Architecture

A pasted YouTube / YouTube Music link is queued, downloaded with yt-dlp, normalized with ffmpeg, scored by independent detection signals, aggregated by rules into a verdict, and explained by Groq for a React UI that polls the job.

Key facts

  • Base URL from VITE_API_BASE_URL, default http://localhost:5214; empty means same-origin.

Key facts

CleanupAcquired and preprocessed audio files are deleted after every run and on recovery.
CancellationShutdown leaves the job in progress; RecoverInterruptedAsync resets it to Pending on next start.
Failure reasonUserFacingException message or a stage-specific text, plus FailedStage; details stay in the log.
Save fallbackIf the final update fails, the job is re-saved as Failed with result and visualization cleared, so polling ends.

04Detection signals

Each IDetectionSignalProvider runs during Analyzing; one that throws is left out.

Metadata clues

implemented
MetadataHeuristicsSignalProvider · Analysis

AI mentions or human-made claims in title, channel, tags and description; weight 0 when nothing is found.

no external dependency

Web research

implemented
GroqWebResearchSignalProvider · Infrastructure

Asks Groq with browser_search whether the track or artist is known AI; links kept only from executed_tools, unbacked claims capped at weight 0.3.

Groq gpt-oss-120bGROQ_API_KEY

Generator fingerprint

implemented
MlDetectionSignalProvider("fakeprint") → FakeprintDetector

Logistic regression over the spectral "fakeprint" left by generator decoders (Suno ≤ 5, Udio ≤ 1.5), weight 0.8.

ML service · numpy / scipyvendored weights.npz

Further signals

none planned
MlService:Detectors

ROADMAP.md lists no new detectors; adding one means a new ML endpoint id in config.

not on roadmap

Aggregation

implemented
WeightedSignalAggregator · Analysis

Rule-based weighted logit sum to AiGenerated / Human / Mixed / Inconclusive (decisive at 0.65); Groq only words the explanation afterwards.

no modelWhisper lyrics + explainer optional
